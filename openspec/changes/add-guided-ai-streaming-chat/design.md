# Design

## Context

现有 Go/MySQL、React、Nginx、班级检索和锁定事务可复用；现有 start/citation SSE 与班级单助手配置需要升级。新版依据为2026-10-14课件 scope、skill-model、session、route、stream、answer、apply 七章。

## Decisions

1. tutor_agents 以自增id、class_id、班内唯一name(64字)、prompt(2000字)、enabled、version和seed_key保存。skills 以自增id、班内唯一name(32字)、trigger_text(120字)、subject_text(32字)、description(2000字)、tools_json、source_text、enabled、seed_key保存。两张绑定表带班级复合外键，防止跨班关系写入。教师写操作事务验证全部绑定ID，失败不部分修改。
2. 技能输入为 source_text 或上传 UTF-8 文件，总长8000字以内。首个空行前为中文元数据行，支持中文/英文冒号；忽略注释。名称、适用条件、启用必填；只接受名称、适用条件、资料、工具、启用五项，工具仅 knowledge_search；拒绝重复字段、未知字段和空正文。原文保留供编辑，空工具表示无工具。
3. 会话增加 agent_id 并锁定。新建请求必须带 agent_id；无可用智能体400，未知/停用/他班ID404。既有会话使用其智能体，不受随后enabled=false影响。教师与学生均只能看到本人本班会话。
4. 每轮在事务内读取智能体当前prompt/version、启用技能及材料绑定，选择技能。用分隔符[,，、;；|]切词，统一小写，子串命中每词1分，最高分胜出，同分小ID，零命中无技能。技能名含解题引导时注入严格引导约束。每条助手消息记录技能ID/名称和配置版本，事务完成后使用本轮快照；教师改动下一轮生效。
5. 检索必须在SQL、Qdrant及回MySQL三个阶段限制class和绑定材料，不能先检索全班再截断过滤。空绑定不调用检索/嵌入。先取4条，再剔除空正文与标题不匹配subject_text的证据，连续编号；正文各800字。检索失败在meta前返回JSON503，保留问题和failed状态，不调用模型。
6. 空prompt回退默认角色。系统消息仅角色、选中技能和平台/引用边界；资料、当前问题和历史均在user/assistant消息。历史末尾6条已完成非空消息，每条500字，包含本轮已保存的问题；用编号资料增强末尾那条user消息，避免问题重复。零命中仍调用模型，不强制固定未找到文案；在推送前以跨chunk状态过滤[n]，防止未定义引用，最终落库文本必须等于delta拼接。
7. meta在检索后最先发送，包含status:ok、skill或null、citations数组及消息ID；delta为新增文本；done在成功提交后发送消息ID和最终引用；error结束失败流。meta引用表示候选证据，最终答案编号必须属于该清单，历史保存当轮证据快照。保持并发409、取消、超时、失败留痕与不伪装完成的保障。
8. 旧opaque会话/消息ID与sequence_no保留，旧标题迁移不改；新标题为新的提问及首题前24字。幂等迁移新增列和外键，旧会话绑定兼容默认智能体，已有提示词拷贝一次到默认智能体，默认绑定原班材料与引导技能。之后回答绝不读取旧表；旧管理API只同步兼容默认智能体，标为deprecated。新教师页面以智能体和技能编辑为中心，所有用户可进入会话选择页。
9. 处理器注解包含路径、权限、请求/响应schema和错误；Go生成器读取源码注解与单独components模板生成openapi.json，go generate和Docker构建都会生成。Swagger使用本地资源。测试检查生成产物一致和所有注册业务路由覆盖。
10. 独立Compose模拟栈覆盖迁移、权限、绑定隔离、文件解析、路由、meta时序、取消和数据库一致性。匹配新版的真实模型验收只用测试数据及本机密钥，保留业务卷；真实模型与模拟证据分别记录。

## Risks / Trade-offs

自然语言无法穷尽证明没有最终答案；使用规范提示词、明确违规输出拦截和真实数学/语文评测。meta提前展示候选证据，不意味着模型已成功或实际引用全部资料，UI只有done后标记完成。保留原事务/错误保证，不采用生成失败伪装成功。课件页面个别流程图与正文冲突时，以scope、answer正文明确的零命中继续生成和四类SSE为准。

## Migration Plan

先独立库跑幂等迁移/新绑定约束和旧会话回填，随后部署新API及前端一起更新协议；新配置增量生效。现有业务库先备份再启动新版本，原账号/密码/材料/消息不删除；旧配置表保留。回滚应用时保留新表/列，禁止删除业务卷。
