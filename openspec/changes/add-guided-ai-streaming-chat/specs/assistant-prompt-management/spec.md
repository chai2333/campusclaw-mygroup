# Spec Delta

## ADDED Requirements

### Requirement: 本班多智能体与绑定管理
系统 MUST 允许教师在本班创建、修改和启停多个智能体，班内名称唯一且1–64字，角色提示词0–2000字，每个智能体绑定零到多个本班技能与材料。绑定未知或他班对象 MUST 返回同形404并回滚全部修改；学生写操作403。学生只可列出/读取已启用本班智能体，教师可查看本班全部配置。

#### Scenario: 创建两个不同助手
- **WHEN** 教师创建数学与语文智能体，绑定不同技能和材料
- **THEN** 两者配置独立，学生能选择已启用者并看不到他班或停用者

#### Scenario: 原子拒绝跨班绑定
- **WHEN** 教师提交含他班或不存在编号的技能/材料绑定
- **THEN** 返回同形404且原配置、名称、版本和全部绑定不变

### Requirement: 配置从下一轮生效与默认角色
系统 MUST 在每轮回答开始读取会话绑定智能体的最新提示词、版本和绑定并固定该轮；空提示词 MUST 回退默认角色而不拒绝回答。后续更新 MUST 只影响下一轮。学生不得修改或通过请求覆盖角色配置。

#### Scenario: 空提示词智能体作答
- **WHEN** 学生使用角色提示词为空的智能体提问
- **THEN** 使用默认角色，继续回答而非返回prompt_not_configured

#### Scenario: 更新发生于生成期间
- **WHEN** 教师在一轮生成中修改提示词或绑定
- **THEN** 当前轮使用原快照，下一轮使用最新配置

### Requirement: 保留历史的幂等增量迁移
系统 MUST 保留现有账号、材料、会话、消息和旧配置表，幂等创建新表/列，将旧会话关联本班兼容默认智能体。旧提示词只在迁移时复制，回答路径 MUST NOT 读取班级提示词表。

#### Scenario: 重复升级已有数据库
- **WHEN** 连续执行两次迁移和启动
- **THEN** 不丢数据、不重复默认智能体/种子技能，原会话仍可读取和追问
