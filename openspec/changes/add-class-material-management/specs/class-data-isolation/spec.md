# Spec Delta

## Purpose

定义班级作为教师与学生共享数据库中的安全边界，使列表、普通搜索、详情、下载与上传全部使用服务端身份确定范围，并以一致拒绝响应和负向测试证明跨班数据无法泄漏。

## ADDED Requirements

### Requirement: 材料列表与搜索只查本班
系统 MUST 根据会话关联用户的当前 class_id 在服务端过滤列表和搜索；客户端 class_id 声明一律忽略。

#### Scenario: 本班查询
- **WHEN** 用户请求 GET /api/materials
- **THEN** 仅返回当前班级 ready 材料，来源为数据库。

#### Scenario: 伪造班级查询
- **WHEN** A 班用户在 query、Header 或请求体声明 B 班
- **THEN** 列表仍为 A 班，不切换班级，不包含 B 班标题、正文或元数据。

#### Scenario: 搜索隔离
- **WHEN** A 班用户用 B 班材料独有的标题或正文搜索
- **THEN** 返回空匹配；查询注入不能改变班级条件。

### Requirement: 材料对象及文件防枚举
系统 MUST 对 GET /api/materials/{id} 及 /file 独立验证会话和归属；跨班、非 ready 与不存在使用同形 JSON 404，不泄漏任何对象数据。

#### Scenario: 本班详情和文件
- **WHEN** 同班教师或学生请求 ready 材料详情/文件
- **THEN** 返回 200 对应正文/文件及允许元数据，不含存储路径。

#### Scenario: 跨班与不存在同形
- **WHEN** A 班用户分别请求 B 班 ID 和不存在 ID 的详情及下载
- **THEN** 两者状态码、错误结构、文案、内容类型与缓存策略一致且为 404，无标题/正文/路径。

#### Scenario: 对象访问不可旁路
- **WHEN** 直接构造 URL 或绕过界面请求跨班对象
- **THEN** 仍返回 404，不能先读取文件再判断归属。

### Requirement: 上传归属由服务端决定
系统 MUST 忽略客户端角色与班级声明，在授权后将材料和知识条目绑定当前教师的服务端班级。

#### Scenario: 教师伪造目标班级
- **WHEN** A 班教师提交合法文件并声明 class_id=B
- **THEN** 上传成功的材料及全部知识条目均归 A 班，B 班数据不变。

#### Scenario: 学生伪造权限
- **WHEN** 学生声明 teacher 并指定任意班级上传
- **THEN** 返回 403，无文件、材料或知识条目新增。

### Requirement: 无班级身份不能访问材料
系统 MUST 拒绝缺少有效班级归属的认证用户读取、搜索、下载或上传材料。

#### Scenario: 缺失或无效班级
- **WHEN** 已认证无有效班级的用户调用任意材料接口
- **THEN** 返回 403，无业务内容或写入副作用。

### Requirement: 知识来源与班级一致
系统 MUST 保证材料及其知识条目的班级非空、有效且一致，知识条目可追溯至材料和上传者。

#### Scenario: 数据约束
- **WHEN** 尝试写入空班级、无效材料关联或不同于材料班级的知识条目
- **THEN** 持久化层拒绝，不能产生跨班关联或无归属数据。

#### Scenario: 授权更新
- **WHEN** 数据库修改用户班级后再次访问原班材料
- **THEN** 新请求使用新班级；原班对象返回 404。

### Requirement: 审计不泄漏业务秘密
系统 SHALL 在服务端区分不存在与跨班拒绝原因以便排障，对外响应 MUST 保持同形。

#### Scenario: 审计拒绝
- **WHEN** 触发不存在和跨班访问
- **THEN** 受控日志记录操作者、操作、资源 ID 与真实原因，不含密码、Cookie、完整正文或文件存储路径。
