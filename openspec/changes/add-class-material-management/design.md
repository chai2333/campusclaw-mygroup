# Design

## Context

当前仓库已有 Flask + SQLite + Argon2id + 服务端模板实现，且存在本地持久化数据。用户已选择将迭代 1 完整范围迁移到第 3 课示例栈。动机与范围见 proposal；本设计描述目标实现，不表示新栈已完成。原版本完成的 42/44 项任务不作为新栈验收证据。

## Goals / Non-Goals

**Goals:** 通过同源入口建立 Go 服务端信任边界；迁移已有数据；补齐安全合同与完整 Web 体验；使 Compose、故障响应与验收可复现。

**Non-Goals:** 见 proposal；仅单 API 实例，不引入 Redis、消息队列、向量库、独立管理后台或公网基础设施。

## Decisions

### Decision 1: Go、MySQL 与 React 三服务架构

后端使用 Go 标准库 `net/http`、`database/sql` 与 MySQL 驱动，分为 `backend/cmd/server` 与 `internal/{config,db,auth,materials,knowledge}`；前端采用 React 18 + TypeScript + Vite、React Markdown + Remark GFM、原生 CSS。MySQL 8.0 使用 InnoDB、utf8mb4。依赖版本和镜像具体版本在实施时核对兼容性并锁定，不能直接使用不受控的 latest。

浏览器 → Nginx web → Go api → MySQL db。只有 web 发布宿主端口，默认 `WEB_PORT=8080`。Nginx 代理 `/api`、`/health`、`/ready`；`/uploads` 明确拒绝且不落到 SPA fallback。前端构建产物由 Nginx 提供，上传卷仅 API 挂载。Vite 开发代理使用同样路径。

SPA shell 不含业务数据，但 `/materials` 等受保护文档请求仍由 Nginx auth_request 调用 API 身份检查后放行；无会话跳转 `/login`，依赖故障显示 503。直接 API 请求保持 JSON 401，不被入口改写成 HTML 或 200。静态壳、前端隐藏按钮均不承担最终授权。

备选：继续 Flask 单体虽能满足行为，但用户选择课件栈；直接映射 API/DB 端口增加旁路，故不采用。为前端引入 UI 组件库会偏离本次原生 CSS 设计系统，故不采用。

### Decision 2: 数据模型与幂等种子

保留 `classes`、`users`、`sessions`、`materials`，将 `knowledge_chunks` 映射为 `knowledge_entries`。材料 ID 保持字符串以兼容旧 ID；知识条目保存 `material_id`、`class_id`、`chunk_index`、`content`，唯一约束为材料＋分段序号。材料保存标题/原文件名、上传者、班级、存储键、入库时间和 ready 状态；分段按序重建完整正文且不丢失分隔符。材料与知识条目的班级非空、建索引，并通过联合约束保证两者班级一致。用户角色只能 teacher/student；迁移中的无班级用户仍可认证，但材料访问返回 403。

初始化 A/B 两班及既有 `a-teacher`、`a-student`、`b-teacher`、`b-student` 账号；保留这些账号名，避免迁移后用户失去熟悉入口。每班增加一份具有稳定种子键、可区分标题、原文件及对应正文的示例材料。重复启动不复制、不覆盖密码和用户上传。种子与迁移模式分离，迁移完成后再补缺失种子。

备选：为匹配示例更名为 teacher_a 会破坏既有账号，拒绝；一班一个数据库超出本课成本。

### Decision 3: 服务端会话、密码与登录限流

使用 `crypto/rand` 生成至少 256 位熵的随机会话 ID，Cookie 只含不透明 ID；MySQL sessions 保存用户关联、创建及过期时间，不复制角色或班级。`SESSION_SECRET` 用于 HMAC-SHA256 派生存储侧会话查找键，数据库不必保存可直接复用的原始 ID；它不得取代密码学随机源。认证请求连接当前用户记录，每次重新读取角色与班级。成功登录在事务中撤销请求携带的旧会话、创建新会话；登出撤销并清 Cookie，过期会话拒绝并清理。

Cookie 设置 HttpOnly、SameSite=Lax、Path=/，本地 development HTTP 不加 Secure，非开发环境加 Secure。TTL 默认 28800 秒，正整数环境变量配置。所有身份及材料响应 no-store，不在 localStorage 保存身份声明、会话或材料；只允许保存主题/视图偏好。

新账号使用 bcrypt（cost 12）。现有 Argon2id 哈希原样导入，Go 兼容其 PHC 参数和常量时间结果比较；有效登录后，在密码符合 bcrypt 输入长度时升级哈希，超出 bcrypt 长度限制的历史密码继续使用 Argon2id，不能静默截断或锁住账号。新种子密码超过 bcrypt 72 字节限制时配置校验失败。迁移不能从旧哈希直接换算 bcrypt，也不要求明文导出。

用户名不存在、密码错误、达到限流三种情况返回相同 `401 {"error":"invalid_credentials"}`。不存在或被锁定时仍执行与新账号同成本的虚拟 bcrypt 比较；旧哈希算法差异作为迁移风险记录，不能声称网络耗时恒定。限流键为规范化用户名＋可信来源 IP，默认 300 秒窗口内 5 次失败后锁定 300 秒，锁定期即使正确密码也拒绝，成功解锁后的登录清理失败计数。参数均可配置且必须为正数。

限流使用单进程、受互斥保护、有过期淘汰与容量上限的内存状态；重启会清空，部署明确只允许一个 API 实例。Nginx 覆盖来源 IP 头，API 仅信任配置的内部代理，忽略客户端伪造的转发头。过期清理不可因请求量无限增长而占满内存。

备选：JWT 无法直接满足即时撤销；浏览器缓存角色不能作为授权依据；Redis 共享限流留给多副本迭代。

### Decision 4: 班级隔离与防枚举

列表/搜索 SQL 始终附加服务端班级条件；请求 query、Header、JSON、multipart 中的 role/class_id 不参与授权，班级声明直接忽略。上传由当前数据库用户班级绑定。

对象详情和文件在内部按 ID 取行，然后检查班级和 ready 状态；检查完成前不能读取正文、打开文件或序列化元数据。跨班与不存在返回相同 `404 {"error":"not_found"}`、相同内容类型及缓存策略。日志记录 actor、操作、资源 ID、结果原因，不记录 Cookie、密码、正文或存储路径。无班级身份和学生上传返回 403；认证有效但数据库查询失败返回 503。

备选：联合 ID＋班级查询同样可以隔离，但本次采用课件的先取行再校验，便于内部审计区分真实原因；返回 403 给跨班对象会暴露存在性，故统一 404。

### Decision 5: 同步上传与失败零残留

鉴权、角色、班级校验先于 multipart 解析。仅接受 `.txt/.md`、非空（全空白也拒绝）UTF-8 文本；允许与格式相符的 MIME，浏览器通用二进制 MIME 仍须严格验证内容，拒绝明显二进制签名或伪装。扩展名大小写规范化，默认文件上限 2097152 字节，环境变量可调整；HTTP 有限额读取，已知超限立即拒绝，未知长度达到上限即终止，不能先无限量读入内存。

文件名只供显示；随机存储键生成路径。multipart 中只有一个 file，缺失/重复文件返回 400。校验和解析完成后写受控临时文件，开始 MySQL 事务，插入材料及全部知识条目，将临时文件移入最终目录，再提交事务；成功返回 201。任何失败回滚两表并删除本次临时/最终文件，错误中不回显路径或正文。数据库故障返回 503；存储等内部故障返回 500。失败原因进入脱敏日志，不留 failed 材料行。

数据库与文件系统不能提供真正的跨资源原子事务。为覆盖进程崩溃窗口，API 启动时在就绪前核对存储键与已提交记录，清理未关联临时/最终文件；清理失败保持未就绪并记录脱敏原因。扫描只限该应用专属上传卷，不遍历旧源备份或用户其他目录；运行期间不扫描正在处理的请求文件。迁移模式完成核对前不启用孤儿清理。

备选：旧状态机保留 failed 行不符合新的零残留合同；异步队列增加处理中状态和重试范围，本次不采用。

### Decision 6: 材料读取、下载与前端搜索

`GET /api/materials` 查询当前班级 ready 材料，包含 ID、标题/原文件名、上传者、班级、入库时间及正文供本班筛选；支持 `q` 时只在同一班级标题和知识正文中做参数化普通子串查询。无向量化、相关性排序或跨班搜索。列表与网格共享同一查询结果；没有材料和无搜索匹配显示不同空状态。

详情按知识条目顺序返回完整正文、来源与元数据，隐藏存储键和绝对路径。文件下载先鉴权/隔离再读文件，使用 attachment、经安全编码的原始文件名和 nosniff；丢失文件返回同形 404。不存在 `/uploads` 静态访问通道。

备选：直接静态暴露文件无法执行班级鉴权；硬编码列表不能证明知识入库。

### Decision 7: 完整 Web 行为与原生 CSS 设计系统

两类主页面为登录和材料；详情通过材料页的路由/面板展示。刷新、重开标签或恢复页面均用 `/api/me` 确认身份；上传入口只由其 role 决定，任何业务 401 清内存状态回登录，403/404 按语义展示，503 显示服务不可用且不误清会话。

定义北大红品牌 token（本项目取 #8C1515）、浅色/深色背景与文字 token、间距/字号/焦点状态。首次跟随系统主题，手动选择后保存偏好；列表/网格切换保持搜索条件。320px 手机至桌面布局可用，无页面级横向溢出，表格可在自身容器滚动；按钮与输入有可访问名称及可见键盘焦点。

命令面板由 Cmd/Ctrl+K 打开，支持键盘上下选择、Enter 执行、Escape 关闭并恢复焦点；提供本班材料搜索/打开、主题/视图切换，教师可打开上传，学生无上传命令。不得包含其他班级缓存。

XHR 上传显示字节进度、禁用重复提交；传输 100% 后展示“正在入库”，收到 201 才显示成功并重新查询列表。失败显示可读错误，允许重试。toast 与页内状态通过 aria-live 通知，错误不只依赖颜色。

`.txt` 以转义纯文本显示；`.md` 使用 React Markdown + Remark GFM 支持表格、列表、代码与任务列表；不启用 raw HTML，拒绝 javascript 等危险 URL。课件排除的“在线预览”在本项目解释为 PDF/Office 等通用文件预览，不排除明确要求的 txt/md 正文展示。

备选：将 role 存 localStorage、直接注入 HTML、用上传 100% 宣告入库成功都会破坏行为合同，拒绝。

### Decision 8: 配置、Compose 与探针

配置包括 APP_ENV、SESSION_SECRET、DB_HOST/PORT/NAME/USER/PASSWORD、UPLOAD_DIR、MAX_UPLOAD_BYTES、SESSION_TTL_SECONDS、SEED_TEACHER_PASSWORD、SEED_STUDENT_PASSWORD、LOGIN_MAX_FAILURES/WINDOW_SECONDS/LOCK_SECONDS、可信代理范围及 WEB_PORT。秘密必填无默认，数值校验正数；`.env.example` 列出全部变量及非敏感默认。真实 `.env`、数据库、上传、迁移导出与备份全部排除 Git 和镜像。

配置迁移时，将旧 `SECRET_KEY` 显式替换为新 `SESSION_SECRET`，沿用本地 SEED_* 密码配置并增加数据库凭据；不能把旧 SQLite 的 DATABASE_PATH 误用作 MySQL 配置。新旧环境文件分别保留于 Git 忽略位置，迁移前备份，秘密值不写进终端输出或说明文档。现有账号密码由迁移后的哈希决定，修改种子环境变量仍不会重置已有密码。

MySQL 初始化管理员凭据只供 db 初始化，绝不下发 api；api 使用仅对应用库有必要权限的普通账号。镜像多阶段构建，API 和 Web 以非 root 用户运行。命名卷分别保存 MySQL 和上传，web 不挂上传；api/db 不发布端口。api 对 DB 连接做有截止时间的指数退避重试，超时脱敏退出；不能仅依靠 depends_on。

`/health` 无需认证，仅判断 API HTTP 处理存活，不查数据库和上传目录。`/ready` 无需认证，做轻量 DB 查询及上传目录检查，成功 200，否则 503，仅返回最小状态。Compose 的 API 就绪 healthcheck 使用 `/ready`，不配置因 unhealthy 自动重启的逻辑；web 代理 `/health` 用于端到端存活检查。必需配置缺失时服务不启动。

备选：用单个 `/health` 混合依赖检查会混淆存活与就绪；把 DB 故障变成 401 会让用户无意义地重新登录。

### Decision 9: 既有数据迁移与回滚

单机维护窗口内停旧写入，制作 SQLite 一致性备份与上传文件副本，记录计数及校验和；源卷只读保留。迁移工具导出显式字段，再导入空 MySQL 与新的上传卷：保留用户/班级/材料 ID、账号、密码哈希、时间、上传者、正文及分段序号，按 storage_key 复制文件。旧 processing/failed 材料不发布到新库，完整保存在只读源备份和迁移异常清单；缺文件、班级不一致或重复冲突必须中止并报告，不静默丢弃 ready 材料。

迁移按稳定源 ID 幂等，仅允许相同内容重复导入，冲突停止；导入过程不服务业务。旧 sessions 不迁移，切换后所有用户重新登录。新种子在迁移核对后补缺。验收比较各实体计数、ID、归属、正文与文件校验和，并验证旧密码仍能登录。

切换前保留旧镜像/代码版本和源卷；在允许新写入前验证新栈。失败则停新服务、恢复旧入口及源卷。若新栈已产生业务写入，不能直接切回陈旧 SQLite，必须先备份新数据并制定反向迁移，不能覆盖丢失数据。禁止将 `down -v` 当迁移步骤。

备选：删除数据库重新 seed 会丢失材料和账号变更；明文导出密码既不可行也不安全。

### Decision 10: 可复核交付与课件解释

README 必须包含范围/不做项、单实例限制、配置说明、账号与密码来源、默认入口、health/ready、404 语义、迁移和回滚，以及从干净目录启动步骤。保留每条 Scenario 的命令、关键输出、通过/失败和未运行原因；记录三项核心 ADR（会话/租户、404、事务清理）及探针决策，引用本文件。

课件对“会话含角色”与“每次查用户”、内存会话与持久化表有混用：以当前用户表＋MySQL sessions 为准；只有限流在进程内。原有三能力边界足够覆盖增量，不创建新的 spec 文件。课程发布还需同伴跨班互验和作业提交；只准备资料，不虚构外部验证或自行代发。版本标签建议 `v0.1.0-auth-upload`，实施完成后指向已验收提交。所有实施任务完成并验证后，另行归档并同步主规格，不在本次文档更新中执行。

## Interface Contract

| Method / Path | Result / Authorization |
| --- | --- |
| POST /api/login | JSON username/password；200；非法结构 400；失败/锁定同形 401 |
| GET /api/me | 200 当前 id/username/role/class_id；无效会话 401 |
| POST /api/logout | 有效会话 200 并撤销/清 Cookie；无效会话 401 并清 Cookie |
| GET /api/materials?q= | 本班列表/普通搜索 200；无会话 401；无班级 403 |
| POST /api/materials | 教师 multipart file；201；学生 403；校验 400；超限 413 |
| GET /api/materials/{id} | 本班正文/元数据 200；跨班/不存在 404 |
| GET /api/materials/{id}/file | 本班 attachment 200；跨班/不存在/文件缺失 404 |
| GET /health | 公共存活检查 200，不检查依赖 |
| GET /ready | 公共依赖就绪检查 200/503 |

所有依赖数据库的接口遇到 DB 故障返回 503；500/503/4xx 错误不得携带密钥、正文、堆栈或磁盘路径。旧 `/login` 仅为页面，不恢复传统表单登录。

## Risks / Trade-offs

- [跨栈迁移丢数据] → 源备份、只读导入、ID/正文/文件校验、切换前回滚演练。
- [数据库与磁盘提交并非同一事务] → 请求内补偿、启动前对账、清理失败不就绪。
- [历史 Argon2id 与 bcrypt 耗时不同] → 双算法正确校验、虚拟比较、失败限流与逐步升级，不能宣称恒定响应时间。
- [内存限流重启清空] → 明确单实例及该局限，保留可替换适配边界。
- [课件体验要求增加工作量] → 每个交互均有独立任务与浏览器验收，不以截图替代后端负向用例。
- [已有 42/44 的统计被误当新栈完成] → 重新建立迁移任务清单，全部从未完成开始，保留历史说明。

## Migration Plan

1. 建立新栈构建、配置、数据模型及迁移工具，保留旧运行环境。
2. 在隔离测试数据上验证迁移和回滚，再实现认证、授权、材料与前端。
3. 完成新栈自动测试、浏览器及三服务 Compose 验收。
4. 维护窗口备份并迁移真实本地数据，核验后切换入口；不能删除旧卷。
5. 完成证据、同伴互验和版本交付，随后使用归档流程同步主规格。
