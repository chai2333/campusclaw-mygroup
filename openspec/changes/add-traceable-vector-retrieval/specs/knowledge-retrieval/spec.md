# Spec Delta

## Purpose

使学生与教师能够在当前班级材料中使用关键词、语义向量或混合模式检索可追溯片段，并让系统只依据这些片段生成带来源引用的简短回答。

## ADDED Requirements

### Requirement: 知识正文与检索切片分别保存

系统 MUST 保留上传时的知识库原文，并将检索切片作为独立记录保存。每个切片 MUST 包含稳定标识、所属材料和知识正文标识、班级、从零开始的切片序号、切片正文、字符起止位置和索引状态。原文 MUST NOT 因切分、嵌入或检索预处理而被改写。

#### Scenario: 原文与切片分别存在
- **WHEN** 教师成功上传一份可入库材料
- **THEN** 系统保留完整原文，并另外生成带序号和位置的检索切片

#### Scenario: 预处理不改写原文
- **WHEN** 自定义切分启用移除 URL、移除邮箱或折叠空白
- **THEN** 预处理仅影响待切分和待嵌入文本，保存的知识正文与原始材料保持不变

#### Scenario: 预处理后的字符位置
- **WHEN** 预处理改变了待切分文本
- **THEN** 切片字符区间明确对应预处理后的文本，且系统不把它声称为原文件字符下标

### Requirement: 系统支持三种切分策略

系统 MUST 支持 `auto`、`custom`、`hierarchy` 三种切分策略。未指定策略及种子材料补索引时 MUST 使用 `auto`。

#### Scenario: 自动窗口切分
- **WHEN** 使用 `auto` 策略处理普通正文
- **THEN** 系统以最多约 800 字、相邻约 80 字重叠进行切分，并依次优先在空行、换行、句号处断开，无法找到断点时才按最大长度截断

#### Scenario: 自动策略忽略自定义参数
- **WHEN** `auto` 请求同时携带自定义长度、重叠或预处理参数
- **THEN** 系统仍使用固定的自动策略参数，不应用这些自定义值

#### Scenario: 自定义切分参数有效
- **WHEN** 教师使用 `custom` 策略并提供 100 至 2000 字的最大长度、0% 至 50% 的重叠比例以及换行、空行或句号分隔符
- **THEN** 系统按这些参数切分，并在没有可用断点时按最大长度截断

#### Scenario: 自定义切分参数越界
- **WHEN** 自定义最大长度或重叠比例超出允许范围，或分隔符不受支持
- **THEN** 系统拒绝请求且不替换既有索引

#### Scenario: Markdown 标题层级切分
- **WHEN** 对 Markdown 正文使用 `hierarchy` 策略
- **THEN** 系统按 `#`、`##`、`###` 标题分章，标题保留在所属切片中，超长章节继续按自动窗口规则切分

### Requirement: 切片嵌入与向量记录可关联

系统 MUST 为切片请求固定维度的向量嵌入，并在向量索引中以切片 ID 作为向量主键。向量记录 MUST 仅携带班级、材料、知识正文、切片 ID 和切片序号等关联标识，不得复制切片正文。向量距离 MUST 使用余弦度量。

#### Scenario: 两库通过切片 ID 关联
- **WHEN** 某切片成功完成嵌入
- **THEN** 向量主键、MySQL 切片 ID 和向量 payload 的切片 ID 相同，并可由该 ID 回表取得正文

#### Scenario: 向量记录不含正文
- **WHEN** 检查任一向量记录的 payload
- **THEN** payload 只包含关联标识，不包含原文、切片正文、会话或凭据

#### Scenario: 嵌入失败保留正文
- **WHEN** 材料已保存但切片嵌入失败
- **THEN** 系统保留材料、原文和对应切片，将切片标记为 `failed`，且不留下该切片的不完整向量记录

### Requirement: 教师可以重建材料索引

系统 MUST 允许本班教师使用本次请求指定的切分策略重建材料索引。重建 MUST 删除该材料旧切片和旧向量，再写入新切片与向量；只有新索引状态为 `ready` 后才可检索。学生 MUST NOT 重建索引。

#### Scenario: 使用新策略重建
- **WHEN** 本班教师对已有材料提交合法的新切分策略
- **THEN** 旧切片和向量被替换，新切片的序号、区间、策略和向量与本次参数一致

#### Scenario: 未重建时保留旧索引
- **WHEN** 已入库材料没有收到重建请求
- **THEN** 系统继续使用该材料现有切片，不因全局默认值变化而自动重切

#### Scenario: 学生尝试重建
- **WHEN** 学生直接调用材料索引重建接口
- **THEN** 系统返回 `403`，且旧切片和向量保持不变

#### Scenario: 重建过程中嵌入失败
- **WHEN** 旧索引已删除而新切片嵌入失败
- **THEN** 系统保留材料和失败状态的新切片，不返回过期旧向量，也不把失败切片作为检索结果

### Requirement: 检索支持关键词、向量与混合模式

系统 MUST 支持 `keyword`、`vector`、`hybrid` 三种检索模式；未指定模式时 MUST 使用 `hybrid`。空白查询 MUST 返回 `400`。每种模式 MUST 在排序前执行自己的绝对相关性过滤，不得用明显弱相关的切片凑足数量。

#### Scenario: 关键词检索
- **WHEN** 用户以 `keyword` 模式查询原文中出现的词
- **THEN** 系统仅使用本班 ready 切片的中文 ngram 全文索引并按全文相关度排序，不生成问句向量，也不访问向量服务

#### Scenario: 向量检索
- **WHEN** 用户以 `vector` 模式提交与原文语义相近的问句
- **THEN** 系统生成问句向量，以当前班级过滤向量候选，丢弃余弦相似度低于 0.35 的候选，并按相似度由高到低返回

#### Scenario: 默认混合检索
- **WHEN** 用户没有指定检索模式
- **THEN** 系统同时执行关键词与向量路径，并按 `hybrid` 规则返回结果

#### Scenario: RRF 融合排序
- **WHEN** 用户以 `hybrid` 模式检索且两条路径各有过滤后的候选
- **THEN** 系统以 `k = 60` 的倒数排名融合计算最终次序，某切片缺席的路径不贡献分数，且不直接相加全文分数与余弦相似度

#### Scenario: 空白查询
- **WHEN** 查询为空或规范化后只包含空白
- **THEN** 系统返回 `400` 且不执行全班扫描、嵌入或向量查询

#### Scenario: 无相关候选
- **WHEN** 选定模式过滤后没有本班候选切片
- **THEN** 系统返回 `200` 和空的 `hits`，不泄露其他班级是否存在候选

### Requirement: 检索范围只由登录会话班级决定

系统 MUST 仅从当前已认证用户上下文读取 `class_id`。查询字符串、JSON、表单或请求头中的客户端班级和角色声明 MUST 被丢弃。关键词路径 MUST 按会话班级和 `ready` 状态过滤；向量路径 MUST 先按同一班级过滤，再以同一班级和状态回 MySQL 取正文。

#### Scenario: 教师和学生检索本班材料
- **WHEN** 有班级归属的教师或学生提交检索请求
- **THEN** 两种角色都只能收到其当前班级的 ready 切片

#### Scenario: 伪造其他班级编号
- **WHEN** A 班用户在请求中携带 B 班 `class_id`
- **THEN** 系统仍使用 A 班会话范围，响应中不出现 B 班切片

#### Scenario: 跨班关键词表现为无命中
- **WHEN** A 班用户查询一个只存在于 B 班正文中的词
- **THEN** 系统返回 `200` 和空 `hits`，不以 `403`、`404`、数量或元数据暗示 B 班材料存在

#### Scenario: 向量候选回表再次隔离
- **WHEN** 向量服务错误地返回其他班级的候选 ID
- **THEN** MySQL 回表班级检查排除该候选，响应不包含其正文或来源

#### Scenario: 用户没有班级归属
- **WHEN** 已认证用户没有关联班级并请求检索或问答
- **THEN** 系统返回 `403` 且不访问任何班级知识内容

### Requirement: 每条命中均可追溯至原材料

系统 MUST 以切片为单位返回命中。每条命中 MUST 至少包含材料 ID、材料标题、切片 ID、切片序号、字符区间、从 MySQL 切片正文取得的摘录以及打开受保护材料的引用。响应 MUST 包含所选模式适用的路径分数和名次以及最终名次，不得暴露存储键、磁盘路径、服务凭据或其他班级元数据。

#### Scenario: 命中包含完整来源
- **WHEN** 本班 ready 切片被检索命中
- **THEN** 用户可以看到标题、切片序号、字符区间和原文摘录，并可打开对应材料核验上下文

#### Scenario: 摘录来源是 MySQL
- **WHEN** 系统序列化向量检索结果
- **THEN** 摘录由通过班级复核的 MySQL 切片正文生成，而不是从向量 payload 读取

#### Scenario: 同一材料有多个命中
- **WHEN** 同一材料的多个切片分别命中
- **THEN** 每个切片独立返回，并以切片 ID、序号和区间区分来源位置

#### Scenario: 来源材料不可用
- **WHEN** 候选的材料不存在、未就绪或不属于当前班级
- **THEN** 系统排除该候选且不返回其标题、摘录或引用

### Requirement: 检索依赖故障遵循模式语义

系统 MUST 让关键词检索独立于嵌入和向量服务运行。嵌入或向量服务不可用时，`keyword` MUST 继续工作，`vector` 与 `hybrid` MUST 返回 `503`，不得把依赖故障伪装为正常空结果或伪造相似度。

#### Scenario: Qdrant 停止时关键词仍可用
- **WHEN** 向量服务不可用且用户选择 `keyword`
- **THEN** 系统仍从 MySQL 返回本班关键词结果

#### Scenario: Qdrant 停止时向量模式失败
- **WHEN** 向量服务不可用且用户选择 `vector` 或 `hybrid`
- **THEN** 系统返回 `503`，不返回旧候选或编造向量分数

#### Scenario: 嵌入服务不可用
- **WHEN** 问句向量生成失败
- **THEN** `vector` 与 `hybrid` 返回 `503`，而后续对话模型不会被调用

### Requirement: 问答只依据本班混合检索结果

`POST /api/ask` MUST 对当前问题执行本班 `hybrid` 检索并最多选择前 4 条 ready 切片。客户端提供的 `system` 消息 MUST 被丢弃；系统提示 MUST 由服务端生成。对话模型只能接收当前问题以及编号后的材料标题、切片序号和切片正文，不得接收向量分量或其他班级内容。

#### Scenario: 有依据时生成简短回答
- **WHEN** 混合检索得到一个或多个本班切片
- **THEN** 系统调用对话网关生成只依据这些切片的简短回答，并返回使用的 `hits` 和 `citations`

#### Scenario: 客户端 system 消息无效
- **WHEN** 问答请求携带客户端自定义 `system` 指令
- **THEN** 系统丢弃该指令，只使用服务端提示与本班检索证据

#### Scenario: 无依据时不调用模型
- **WHEN** 混合检索没有保留任何候选
- **THEN** 系统返回 `200`、回答“资料中未找到相关内容”以及空 `hits` 和 `citations`，并且不调用对话网关

#### Scenario: 对话网关失败
- **WHEN** 已有检索依据但对话网关超时或失败
- **THEN** 系统返回 `503`，不生成无引用的替代答案

### Requirement: 回答引用与来源列表一致

存在依据的回答 MUST 使用 `[1]`、`[2]` 等编号引用，编号顺序 MUST 与 `citations` 数组一致。每条 citation MUST 提供与检索命中相同的可追溯信息和受保护材料引用。

#### Scenario: 回答编号对应引用数组
- **WHEN** 回答引用两条检索依据
- **THEN** 回答中的 `[1]`、`[2]` 分别对应 `citations[0]`、`citations[1]` 的材料与切片

#### Scenario: 引用可以打开原材料
- **WHEN** 用户选择任一 citation
- **THEN** 客户端通过现有受保护材料详情打开来源，继续执行认证和班级授权

### Requirement: 检索基础设施不向客户端暴露

浏览器 MUST 只访问本站应用 API。向量数据库、嵌入网关和对话网关 MUST 仅由服务端访问，其端口、凭据和内部连接信息 MUST NOT 出现在客户端配置、响应或错误中。用户相关检索与问答响应 MUST 禁止共享缓存。

#### Scenario: 客户端不能直连向量数据库
- **WHEN** 系统按标准 Compose 配置启动
- **THEN** Qdrant 不发布宿主端口，浏览器只能通过已认证的 Go API 使用检索能力

#### Scenario: 服务凭据保持在服务端
- **WHEN** 用户加载前端或检查检索响应
- **THEN** 响应与前端构建产物不包含嵌入、对话或 Qdrant 凭据

#### Scenario: 日志和缓存保护正文
- **WHEN** 检索或问答成功或失败
- **THEN** 响应使用 `no-store`，日志可记录模式、耗时和候选数量，但不记录 Cookie、完整问题、切片正文、向量或密钥
