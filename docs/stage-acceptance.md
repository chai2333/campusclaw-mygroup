- Git 仓库：https://github.com/chai2333/campusclaw-mygroup

## 一、项目简要介绍与功能对应

CampusClaw 是按班级隔离的 AI 学习应用平台。教师可以配置多个智能体应用、角色提示词、资料范围、Skill 与 MCP 工具；学生选择应用，在私有会话中连续提问，接收流式回答、资料引用与工具执行记录。主要技术为 Go、React/TypeScript、MySQL、Qdrant 和 Docker Compose。

| 验收功能 | 实现与入口 |
| --- | --- |
| 多个 AI 应用 | 新安装初始化“默认学习助手”“数学学习助手”“语文阅读助手”三个独立应用；数学、语文应用分别绑定对应内置技能，教师另行勾选需要的资料。当前本机还已有教师配置的“数学助手”“英语写作助手”。学生可选择本班应用；教师管理各自提示词、技能及资料范围。内置应用初始化不会覆盖教师修改或恢复被移除的绑定。 |
| 提示词模板 | 每个智能体保存独立角色提示词及版本，作为每轮 system 消息的一部分；留空使用默认学习助手提示词。当前是可复用角色提示词，没有实现 `{{变量}}` 模板替换引擎。 |
| 知识库检索 | 上传 UTF-8 `.txt`/`.md`，切片与索引，支持关键词、向量、混合检索；聊天只在本班、当前智能体绑定的资料内执行混合检索。 |
| 内置与上传 Skill | 内置数学解题引导、语文解题引导、通用解题引导。支持课程格式文件与自包含标准 `SKILL.md` 的导入、预览、保存、启停和导出。 |
| 外部工具及 MCP | 教师登记允许地址、连接发现、确认并勾选工具；随仓服务提供 `formula_hint`、`unit_convert`，支持聊天调用和审计。当前为 HTTP/JSON-RPC 的受限只读工具接入，不是任意 MCP 传输和全部协议功能的通用客户端。 |

本报告区分平台初始化内容与已有教师配置，按实际支持的格式、工具与传输范围描述能力。

## 二、验证方式和证据

使用独立 Compose 项目 `campusclaw-lesson5-apitest`，不修改本机业务班级及会话。数据库使用 MySQL，检索使用实际 Qdrant 与受控嵌入服务，MCP 使用随仓 Python HTTP 服务；LLM 使用确定性测试模型。测试模型收到的是应用经真实 HTTP 发出的请求，记录的响应也经同一 HTTP/SSE 链路返回。

[完整请求、返回和工具记录](acceptance/llm-http-trace.json) 是审核过的不含凭据的测试证据。`exchanges[].request` 为请求 JSON；`response.body` 为非流式返回；`response.chunks` 和 `end` 为流式返回；`assembled_text` 为拼接结果。不记录 Authorization 请求头，不包含真实模型密钥、MCP 令牌或生产用户对话。名称和编号来自本次临时验收数据。

| 场景 | 发送给聊天模型的 HTTP 请求数 | 结果 |
| --- | ---: | --- |
| 提示词 + 资料，不绑定 Skill | 1 | 角色提示词存在；无技能正文；无 MCP 声明 |
| 提示词 + 资料 + Skill | 1 | 选中技能正文完整存在；原始文件头部不作为整体传入 |
| 自动判断，模型选择跳过工具 | 2 | 一次工具决策、一次最终流式回答；无实际工具执行 |
| 必须调用，普通自然语言问题 | 3 | 两次工具决策、一次最终流式回答；真实 MCP 公式提示工具执行成功 |

自动跳过场景使用 `MCP_SKIP` 测试标记控制模拟模型，是分支验证，不代表真实模型对该问题的选择。必须调用场景使用“速度每小时3公里，运动2分钟，路程怎么求？给我提示。”，没有要求学生写工具名。

## 三、需验证内容 1：每次对话向 LLM 传递什么？提示词是否一起传递？

**结论：提示词会一起传递。一次用户提问可能产生多次 LLM 请求。**

聊天模型接口是 `POST {DIALOGUE_BASE_URL}/chat/completions`。普通最终生成请求的实际顶层参数是：

```json
{
  "model": "apitest-model",
  "stream": true,
  "max_tokens": 2048,
  "messages": [
    {"role": "system", "content": "平台规则 + 当前智能体角色提示词 + 选中技能正文（如有）+ 引用约束"},
    {"role": "user", "content": "本次问题 + 检索命中的编号资料片段"}
  ]
}
```

上例的 `content` 是结构说明；逐字完整内容见 JSON 证据。`model` 为测试配置，生产环境读取自己的模型配置；输出上限可配置，测试为 2048。代码没有额外发送 `temperature`、`top_p` 等参数。

system 消息包含平台规则、教师保存的角色提示词、当前命中的 Skill 名称和完整正文（如有）、资料引用和解题引导约束。消息历史只取最近最多 6 条已完成且非空的 user/assistant 消息，每条最多 500 个字符，按时间顺序发送，当前问题包含在其中；不是整个历史会话全文。失败及取消的历史回答不加入。

模型按 SSE 返回：

```text
data: {"choices":[{"delta":{"content":"角色一：参照《数学"}}]}
...
data: [DONE]
```

这是证据中某一条真实返回片段；完整片段列表在 `response.chunks`。应用拼接 `delta.content`，进行引用及回答校验，保存为 assistant 消息，再通过自己的 `meta/delta/done` SSE 协议向浏览器返回。模型原始 SSE 和浏览器 SSE 是两套格式。

验证：四个场景的每条请求均包含测试角色提示词 `STAGE_ACCEPT_PROMPT`；没有绑定技能的场景不存在技能正文，绑定后存在完整 `SKILL_BODY_END` 末尾标记。

## 四、需验证内容 2：绑定知识库是否每次发送全部资料？

**结论：不会。只发送本次检索选出的有限片段。**

流程：当前问题 → 本班且当前智能体绑定资料内混合检索 → 最多取 4 个命中 → 再检查班级、资料绑定和技能资料标题筛选 → 每个片段最多 800 字 → 作为当前 user 消息中的 `<evidence>` 数据发送。

每段包含 `[n]` 编号、材料标题、切片位置、字符范围和片段正文。未命中时不发送资料全文，使用“没有可用资料”的标记。没有绑定资料时跳过检索。`knowledge_search` 是课程技能中的兼容工具引用，不是暴露给模型的原生 function；实际检索由智能体的资料绑定控制，不因 Skill 中省略该引用而关闭。

验证：上传 9442 字测试资料，实际生成 23 个切片。四个场景的每次请求中均只有 4 个 `<evidence>`，而不是 23 个，也不存在完整的 9442 字原文。测试同时断言片段数量上限。理论正文上限为 4×800 字，另加标题和位置等元数据；片段可能重叠，不代表 3200 字互不重复的资料。

向量检索启用时，问题还会经独立的 `/embeddings` 请求转换为向量；该调用与聊天 LLM 的 `/chat/completions` 是不同请求。本次对话证据文件专门记录后者。

## 五、需验证内容 3：绑定 Skill 后是否发送该技能的全部内容？

**结论：仅绑定不一定发送；选中后发送该技能的完整正文，不发送整个技能文件。**

应用只在当前智能体绑定且启用的技能中按问题关键词匹配，每轮最多选择一个。没有匹配时不发送技能正文。

被选中后，`Skill.Description` 正文完整加入 system 消息的 `<skill_description>` 中。文件元数据（适用关键词、启停、资料筛选、工具引用和工具策略）由后端解析用于控制流程，不会把 `source_text` 原样整体塞入模型。标准文件的 `description` 是发现说明，而实际执行正文是 YAML 头部后面的 Markdown；二者不要混淆。作者、许可证、未支持的 `allowed-tools` 等字段不会因此变成模型工具权限。

验证：捕获请求断言正文从首句到 `SKILL_BODY_END` 全部存在；不含课程配置行“工具策略：”；未绑定技能的对照场景不含这段正文。保存接口拒绝超限正文，不通过静默截断实现兼容。

当前仅支持自包含单文件技能，不自动上传或执行 `scripts/`、`references/`、`assets/`。如果外部技能依赖这些文件，需要适配。

## 六、需验证内容 4：执行 Skill 时的逻辑是什么？

1. 服务端从登录态确定用户和班级，读取该会话固定的智能体。
2. 快照智能体提示词、资料绑定及当前技能配置，避免一轮中途改配置造成混用；修改从下一轮生效。
3. 在已绑定且启用的技能中，以问题包含的关键词个数评分，取最高正分；同分选较小技能 ID。零分不选择。
4. 在绑定资料内检索，并按技能资料标题限制过滤，构造编号证据。
5. 把角色提示词、选中技能完整正文、有限历史及证据组装为模型消息。
6. 如技能绑定 MCP 工具，先进行工具决策与受控执行；再将工具结果回填模型上下文。
7. 最终流式生成回答，校验引用与解题引导规则，保存回答和工具调用快照。

因此本项目的 Skill 是“后端确定性路由 + 提示词约束 + 可选 MCP 工具调用”，不是执行上传 Markdown 文件里的任意程序。解题引导校验针对明确的答案声明模式，不保证识别所有语义上的直接给答案。

## 七、需验证内容 5：集成 MCP 后向 LLM 发送哪些参数？

**结论：把本轮选中技能绑定且可用的工具声明作为 `tools` 传入，不把 MCP 服务地址或认证令牌传给模型。**

工具决策请求的实际结构（说明和 schema 只展示一个工具，完整两项见证据）：

```json
{
  "model": "apitest-model",
  "stream": false,
  "max_tokens": 2048,
  "messages": ["与本轮相同的 system、历史、问题和资料消息对象"],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "mcp_19_formula_hint",
        "description": "学生卡在数学公式、方程、面积或行程分析时，给概念、公式与下一步检查提示；不计算最终得数，不给完整解答。query是学生的问题。",
        "parameters": {
          "type": "object",
          "properties": {"query": {"type": "string", "minLength": 2, "maxLength": 500}},
          "required": ["query"],
          "additionalProperties": false
        }
      }
    }
  ],
  "tool_choice": "required"
}
```

`messages` 在实际请求中是对象数组，上例为节省篇幅的结构示意。`mcp_19_...` 中的 19 是本次临时登记的服务器 ID，重跑可能不同。工具名称、说明及参数 schema 来自发现结果，仅限本轮技能候选集；不会发送所有班级或所有服务器的工具。

本次实际模型工具决策返回：

```json
{"choices":[{"message":{"role":"assistant","content":"","tool_calls":[{"id":"call_1","type":"function","function":{"name":"mcp_19_formula_hint","arguments":"{\"query\": \"速度每小时3公里，运动2分钟，路程怎么求？给我提示。\"}"}}]}}]}
```

后端据别名找到已绑定 MCP 服务，检查连接、工具确认、只读标记、JSON Schema 与次数限制，再通过 `POST /mcp` 的 JSON-RPC `tools/call` 实际调用。这一步是应用到 MCP 服务的请求，不是另一次 LLM 请求。MCP 的 Bearer 令牌只由后端传给工具服务。

工具结果以一条 `role:"tool"`、带 `tool_call_id:"call_1"` 的消息回填；模型原先的 assistant `tool_calls` 消息也保留，实现一一关联。本次工具返回了：

> 匀速运动可用s=v×t。先统一速度与时间的单位，检查是否需要单位换算，再自行代入完成关键计算；我不提供最终得数。

- 自动判断：不发送 `tool_choice`，允许模型不调用。
- 必须调用：首个工具决策请求发送 `tool_choice:"required"`，要求至少请求一个候选 MCP 工具；后续轮恢复自动判断。不保证调用全部勾选工具，不保证参数或执行成功。
- 接口忽略 required、决策失败或网关不支持工具决策时，显示“必须调用未完成”并留下拒绝记录，不伪造工具成功。
- 最终回答请求：`stream:true`，保留本轮工具调用与结果消息，移除 `tools` 和 `tool_choice`，确保工具阶段结束。
- 默认最多 3 轮工具决策，每次提问最多 6 次、每会话累计最多 12 次工具记录；达到上限时给出原因，基于已有信息回答。

本次必须调用场景的审计记录为 `formula_hint`、第 1 轮、`status:"ok"`，最终回答使用了工具数据。测试模型的第二次决策返回空调用，因此总计 3 次聊天 LLM 请求、1 次真实 MCP 工具执行。

## 八、本次改进与检查记录

教师现在可在“智能体与技能 → 技能文件”直接勾选已连接发现的 MCP 工具，并选择“自动判断 / 必须调用”；不再要求手写 `工具名@服务器名`。学生正常提问即可。未确认、不可执行工具不可新增勾选；已有失效引用仍可见并可移除。策略随课程文件和标准 SKILL.md 导入、导出及保存。

本次已通过：Go 全量测试（连接隔离 MySQL）、43 个接口回归、前端生产构建与类型检查、20 个 SSE 协议测试、浏览器勾选两个工具并保存/刷新回显验证、多应用初始化和保留教师配置测试、四个真实 HTTP 请求抓取场景、required 参数与策略往返/持久化/失败可见性测试。模拟模型验证的是数据链路与分支行为，不等同于第三方真实模型的准确率和兼容性；本次未重跑真实模型验收，不以已有验证记录代替本次证据。
